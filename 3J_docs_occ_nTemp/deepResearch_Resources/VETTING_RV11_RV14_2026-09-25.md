# Vetting record: RV11, RV12, RV13 and RV14, 2026-09-25

**Why this file exists.** Four Gemini returns (prompts V11 to V14, shared brief `00_MASTER_BRIEF_V2.md`)
came back on 2026-09-24. Nothing from them enters the manuscript until it has passed the 7-step
vetting. None is accepted or rejected wholesale. This file lists what is usable, what is refused and
why, and one table of manuscript actions for the manager. No manuscript chapter was edited.

**No search was run to produce this file.** No DOI was resolved, no web page was opened. Everything
below is arithmetic on the reports' own numbers, a consistency check of each report against itself and
against earlier rounds, or a comparison against a file in this repository. The arithmetic is in the
scratchpad script `vet_rv11_rv14.py` (run with `py -3`); its output is quoted where used.

**Trust rule used here.** A reference is TRUSTED-2J only when the same work appears in the 2J AE
revision's reference list (`2J_manuscript_AE_revised.md`, References, checked field by field against
Crossref on 2026-09-17), and then the 2J metadata is used, not the report's. Every other citation is at
best CANDIDATE-AUTHOR-OPENS. A precise number attributed to a source we cannot open is not usable.

## Step 3. Metadata columns (cities, years, units, basis)

- **Centroid vs peak (RV13, category error).** Our "energy peak hour, circular mean" is the load-weighted
  circular mean of the whole weekday profile (Eq. B.7), that is, a centroid. RV13 compares it with measured
  presence peak intervals (Kastle badge swipes, ATUS shopping) and with electric peak hours. A centroid
  and a peak are different quantities. Presence is also not energy. Table 3 names this row
  "Energy peak hour", which invites exactly this confusion (side finding S4).
- **Kastle measures badge entries** (arrivals), not presence. A presence peak read from swipe counts is
  an inference, and hourly curves as a published product are unverified.
