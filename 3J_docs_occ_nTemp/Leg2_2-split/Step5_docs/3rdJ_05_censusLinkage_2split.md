## 1. Aim

Extend the proven 2J residential census linkage so it carries **both** occupancy channels
through to the BEM-ready schedule table:

- **Residential** — `hom30` (AT_HOME), 48 × 30-min slots — unchanged logic from 2J.
- **Office** — `wrk30` (AT_WORK), 48 × 30-min slots — **new**, plus the `colleagues30`
  co-presence channel and an **office archetype** keyed on Census occupation (NOCS).

The two channels are **not mutually exclusive** (a person can be neither at home nor at work,
e.g. in transit/3rd place). Office activity *modulates* (does not replace) the ASHRAE/NECB
baselines downstream.

## 3. Method

### 3.1 Day-type assignment
`DDAY_STRATA` ∈ {1=Weekday, 2=Saturday, 3=Sunday}, population-proportional **5:1:1**
(`_DDAY_PROBS = [5/7, 1/7, 1/7]`), `seed=42`.

### 3.2 4-tier demographic fallback match (`run_slot_match`, seed 42)
| Tier | Keys | Label |
|------|------|-------|
| T1 | `AGEGRP, SEX, MARSTH, HHSIZE, LFTAG, PR, CMA` + DDAY | `1_Perfect` |
| T2 | `AGEGRP, SEX, LFTAG, PR` + DDAY | `2_Core` |
| T3 | `AGEGRP, SEX` + DDAY | `3_Constraints` |
| T4 | DDAY only | `4_FailSafe` |

Within the matched stratum a pool row is chosen by uniform `np.random.choice`. The pool-row
label is stored as `_pool_idx`.

### 3.3 Channel carry-through (`expand_slot_schedules`)
The matched diary row is pulled by label (`df_pool.loc[_pool_idx]`) and these groups ride
through **identically**: `act30`, `hom30`, **`wrk30`**, and all 9 co-presence channels
(`Alone/Spouse/Children/parents/otherInFAMs/otherHHs/friends/others/`**`colleagues`**`30`) ×48,
plus pool metadata (`CYCLE_YEAR, IS_SYNTHETIC, WGHT_PER, COLLECT_MODE, TELEWORK, WORK_SCHEDULE`).

### 3.4 Authority rules
- **Census authoritative** for shared cols: `AGEGRP, SEX, MARSTH, HHSIZE, LFTAG, PR, CMA, HRSWRK, NOCS, TOTINC` + building cols.
- Pool `NAICS` kept as **`NAICS_donor`** (no NAICS in 2025 Census).
- ID rename vs 2J: `PP_ID → PID`, `HH_ID → SIM_HH_ID`.
- Hard guard: any `_x/_y` suffix collision raises.

### 3.5 Office archetype (bundled into Step 5)
Keyed on Census **NOCS** (manager decision 2026-06-22: bundle into Step 5, not defer to Step 7):

| NOCS | Archetype | is_office |
|------|-----------|-----------|
| 0,1,2 | Office_Knowledge | ✓ |
| 3,4,**5** | Office_Public | ✓ |
| 6 | Office_Sales | ✓ |
| 7,8,9 | NonOffice | ✗ |
| NaN/other | Unknown_NOCS | ✗ |

**NOCS 5 (Arts/culture/recreation) → Office_Public** — manager judgment call (2-channel_split.md
§3.5 did not specify NOCS 5; kept Public because the full-population archetype distribution stays
healthy with it there). Revisit if office BEM gains look off.

### 3.6 Downstream sub-steps
- **5E `--aggregate`** — HH occupancy = **max over members of `hom30`** per slot; **`wrk30` stays per-person** (work is individual, never HH-maxed).
- **5F `--bem`** — 48-slot schema validation for act30/hom30/wrk30, label cols, BEM prep.
- **5H `--exclusion`** — drop agents with AT_HOME < 0.30 (vacancy proxy).
- **5G `--regression`** — validation vs `IS_SYNTHETIC=0` baseline.

## 4. Expected result / test method
Validator `3rdJ_05_censusLinkage_2split_val.py` (full = no `--smoke`). Residential gates inherited
from 2J (AT_HOME ±3pp/slot, top-5 activity ±2pp, Spouse ±3pp, DTYPE exact, night AT_HOME ≥85%,
sleep dominance ≥70%, FailSafe WD ≤10% / WE ≤12%) + **new office gates**: W1 AT_WORK ±3pp/slot,
W2 AT_WORK-by-LFTAG sanity, W3 colleagues co-presence ±3pp, W4 archetype distribution
(NonOffice <60%, Unknown <10%).

### 2026-06-22 — LOCALIZED → ROOT CAUSE: PR join-key coding mismatch (Sonnet, read-only)
Three-cut localization of the selection-concentration. Verdict = **STRATUM-UNMATCHABLE, but the cause is
a recodable join-key mismatch — NOT a Step-4 channel failure.**

- **CUT 1 (DDAY):** matched syn workers split 70.2/17.2/12.6% WD/Sat/Sun — proportional to the 5:1:1 prior,
  **not** weekend-skewed. DDAY is not the cause.
- **CUT 2 (within-stratum availability):** of 6,446 matched syn workers, **99.0% sit in a T2 stratum whose
  synthetic workers are ALL zero-colleagues**; mean availability 0.00%; **0** matched workers had any
  col-bearing donor in-stratum. So it's structural, not a sampling accident.
- **CUT 3 (where the colleagues live):** unique T2 strata holding col-bearing syn workers = 731; census
  worker strata occupied = 389; **overlap = 0 (0.0%).**

**Root cause — PR coding mismatch (hard counts, deterministic groupby):**

| PR range | pool rows | col_nonzero rows | col_nonzero % |
|---|---|---|---|
| PR 1–5 (grouped region codes, = census 1–6) | 57,663 | **0** | 0.00% |
| PR 10+ (actual StatCan province codes 10/11/12/13/24/35/46/47/48/59) | 134,520 | 19,353 | 14.39% |

The two ranges **partition the pool exactly** (57,663 + 134,520 = 192,183) → disjoint, no duplication.
**Every col_nonzero row lives in PR 10+.** The census is aligned to grouped region codes (PR 1–6); the
T2 matcher requires exact PR equality → census agents can only ever reach the 57,663 PR 1–5 rows, all of
which are zero-colleagues. **Consequence is bigger than colleagues: the entire linkage was silently
confined to ~30% of the pool; the PR-10+ 70% (incl. ALL colleagues mass) was structurally unreachable.**
Tiers still looked healthy (98.39% T2) because the reachable 30% is plenty to match against — colleagues
is just the channel that happens to live 100% in the unreachable 70%.

**Disposition — fixable in Step-5, no Step-4 re-open.** Add a province→region remap on the POOL `PR`
(StatCan standard grouping: Atlantic 10/11/12/13, QC 24, ON 35, Prairies 46/47/48, BC 59, Terr 60) to the
SAME scheme the census uses, BEFORE matching. Then full Step-5 re-run + full re-validation. Caveat: this
changes the donor pool for ALL channels (not just colleagues) → the whole scorecard will move (plausibly
*improving* the work-mass / AT_WORK gaps, since the richer PR-10+ rows become reachable). Builder must
read the census alignment to copy its EXACT grouped-PR mapping so pool↔census codes line up.
