What this report compares — and why

What this is. Step 1 of the Leg-2 (two-channel: Residential + Office) pipeline reads four GSS Time-Use cycles (2005, 2010, 2015, 2022) from raw Statistics Canada microdata and writes 8 tidy CSVs (one main + one episode file per cycle). This report checks those 8 CSVs before we move to Step 2 (harmonization), because every later step inherits whatever we read here.

What we compare, and why.

  • Did every column survive the read? (Method 1 — schema, row counts, dtypes) — a column that silently failed to read would corrupt the office split.
  • Are the categories sensible and consistent across cycles? (Method 2) — catches a wrong column being pulled or a value-code shift between cycles.
  • Are the diaries intact? (Method 3 — IDs link, time ordered, minutes sum to 1440, location codes present) — Step 3 tiles these into 48 slots, so a broken diary breaks the schedule.
  • Did the survey weights survive? (Method 4) — weights drive every population estimate downstream.

Each check prints ✅ pass / ⚠️ warning / ❌ fail with the actual number, so the green ticks are backed by values you can read (e.g. "PLACE 2005 — 24 distinct codes, 0% NaN"), not just a colour.

Why this run shows 0 failures (it previously showed 4)

An earlier version of this validator reported 4 FAIL + 22 WARN. All of them were validator bugs, not data problems — the data was never broken. Three mechanisms:

  1. Rename blindness. The reader renames raw PUMF variables to canonical names before writing the CSVs (ACT7DAYS/WHW_110/…→LFTAG/COW/NOCS/HRSWRK). The old validator searched for the raw names, so it declared present columns "missing."
  2. occPRE checked too early. occPRE / AT_WORK are derived at Step 2/3, not at read time. The old validator failed because they weren't in the Step-1 episode file — but they're not supposed to be yet. We now check the raw location source (PLACE/LOCATION) it is derived from.
  3. Telework heuristic. Telework vars are universe-coded (~100% non-NaN is normal); the old ">100% coverage = suspicious" rule was wrong.

To make sure nothing real was swept under the rug, this version is stricter, not looser: it adds Method 4 (weights), diary-completeness, episodes-per-person, activity-code-range, row-count and dtype checks. A genuine read error would now trip one of these. They all pass on the actual numbers.

WHW_110 (the WET_120 PUMF suppression is therefore not a gap here).
On the EPISODE file, occPRE does NOT exist at Step 1 by design: the raw
location source (PLACE for 2005/2010, LOCATION for 2015/2022) is what
AT_WORK is derived from at Step 2/3.  No further action is required.
