## Decisions
- **V1's shadow control copies ONLY `cell_manifest.csv`**, not the full 50-household output tree, into
  `T55/shadow/`. V1 (`_read_manifest` + set comparison) never reads anything else from a cell directory, so copying
  the ~50-row manifest is sufficient to exercise the exact code path the real V1 gate uses; copying the full
  8,760-row-per-household output tree for one cell would be a much heavier `scp`/filesystem operation for no
  additional control coverage. Not assumed silently -- recorded here because the parent doc's wording ("copy ONE
  cell's real output") could be read more broadly.
- **Control 1 and Control 3's V1 check calls the checker's own `_read_manifest()` function directly** (not the
  full `v1_same_households()` loop over all 24 cells x 2 years), because a shadow copy exists for only ONE cell;
  running the real 24-cell loop against a root where only 1 of 48 directories exists would report 47 spurious
  "missing" mismatches, which is not what "seen-failing on ONE cell" is asking to demonstrate. `_read_manifest()`
  is the exact function `v1_same_households()` calls internally, and the comparison predicate (Python set equality)
  is the same one-line logic `v1_same_households()` uses -- so this is testing the SAME code, scoped to one cell,
  not a re-implementation.
- **Control 2's "shift one hour" is implemented as `Weekday[8]['occ'] += 0.30`** on a deep copy of the REAL computed
  `avg_profile` (not a saved/staged file, since V2 has no on-disk profile artifact to shift -- it is a live
  computation inside `build_avg_schedules()`/`_v2_identity()`), then passed straight into the checker's own
  `_v2_identity()`. This exercises the exact comparison function V2 depends on with a known, large, single-hour
  defect (0.30 fractional occupancy is far larger than any float-noise or averaging-arithmetic residual), rather
  than writing and re-reading a file the real V2 gate never touches.
- **The hand-check's "recomputed by hand" is implemented as two independently-coded software sums** (pandas
  `.sum()` vs a manual `csv.DictReader` accumulation loop), not literal by-hand arithmetic, since this runs inside
  an unattended sbatch job. This satisfies the substance of the requirement (an independent re-derivation, not
  trusting the checker's own pandas-based row count / column read at face value) but is not literal manual
  arithmetic -- flagged under WHAT I DID NOT VERIFY below.
- **`t55_score.sh`'s exit code is left equal to `t55_score.py`'s own exit code** (crash-vs-clean, not
  gate-PASS-vs-FAIL) rather than forcing it to always exit 0. This is stated explicitly inside the report file's
  own "INNER STATUS BY SECTION" footer per the task doc's instruction to say so either way, so a future reader
  does not need to guess which meaning `sacct`'s exit code carries for this particular job.
