## Decisions
- **D-T28-A1 (assumed).** B3's "for each of the six metrics and their deltas" is implemented as: each
  metric evaluated separately at 2022 and at 2030 (raw annual value), PLUS the paired 2030-2022 delta --
  18 series per cell (6 metrics x (2 years + 1 delta)), not 6. The task doc does not say whether the
  raw-value test is done for one year or both; testing both is a superset of "the six metrics" and is
  documented here as an assumption, not silently narrowed to one year.
- **D-T28-A2 (assumed).** B3's "the published method (paired Student-t over households)" is applied
  the same way at both N=50 and N=200 (a one-sample Student-t interval on the metric/delta values
  directly, `scipy.stats.t.interval`-equivalent, matching T03's method, T27 Q5) -- i.e. `t28_check.py`
  reports a paired-t half-width AND a mean at N=50 too (not just N=200), even though the task doc's own
  wording ("CI half-widths at N=50 and N=200") only explicitly asks for both half-widths, which requires
  computing the N=50 CI as well.
- **D-T28-A3 (assumed).** B2 "stops B3 until the manager reads it" is implemented as a note in the
  JSON report (`b2_reproducibility.note`), not a hard code gate -- `t28_check.py` still computes and
  writes B3's CSV even if B2 fails, so the collector has full visibility; the manager decides whether to
  trust B3 given a B2 failure, rather than the script silently omitting B3 output.
- **D-T28-A4 (assumed).** `t28_array.sh` reuses `t21_array.sh`'s own choice to leave the warm-up-120
  retry as a Phase-B, post-hoc, separate pass (not inlined), for the same reason T21 gave: on every
  campaign to date this has been a manual sed-patch-and-rerun step applied after undelivered runs are
  identified, not a mechanism that exists as an importable function anywhere in the pipeline.
- **D-T28-A5 (assumed).** Pre-created `T28/logs/` and `T28/out/` on Speed via `scp -r` of local
  placeholder directories (each holding one empty `.keep` file), rather than leaving them for

  "RULE VIOLATION" entry shows `T21/logs/` was pre-created before any array job ran; SLURM's
  `#SBATCH --output` path is resolved and opened by SLURM itself at job dispatch, before the script body
  ever executes its own `mkdir -p`, so the directory in `--output=.../T28/logs/...` needs to exist
