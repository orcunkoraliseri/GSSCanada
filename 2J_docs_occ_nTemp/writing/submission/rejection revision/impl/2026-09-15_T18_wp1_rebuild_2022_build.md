that step in the same place for both arms and records it. Step order between the rake and `--aggregate`:
rake first (the aggregated file must carry raked diaries); if Arm C then fails to reproduce, the collector
reports it and the manager decides — do not try orders by hand.

**No pipeline source edits.** Each arm runs in its own staged repo-layout tree on Speed
(`T18/arm_C/repo/`, `T18/arm_N/repo/`, T17 precedent), with copies of the scripts and only the inputs they
read. The arm trees differ in exactly one file: `outputs_step4/augmented_diaries.csv`. If any script
resolves paths outside its tree (absolute paths, `occ_config.py`), use a wrapper that sets the module
path constants (`AUGMENTED_DIARIES` at `05_census_linkage.py:33`, `_FULL_SCHED_PATH` at
`05_postlink_rake.py:31-35`, etc.) before calling the functions, and record every constant set.

**Mitigation rules (spec §5b) as built:**
1. Donors = all 2022 diaries, real + synthetic. Done by Arm N's input.
2. Relax keys within 2022 only, in existing tier order: already what the 4-tier fallback does
   (`05_census_linkage.py:75-82,111-213`) when the pool is 2022-only. No new code.
3. Reuse cap: the linkage has no cap control (`np.random.choice` with replacement, `:184-193`), so no
   cap is added (that would be a source change). Reuse is reported instead (N4).
4. N4 metrics below. 5. Tier-1 drop > 10 points triggers the manager's extra lever (T18b), before any Step-8 run.

**Side effect to record, not to fix:** `colleagues30` was forced to 0 for 2005/2010 synthetic diaries;
a 2022-only pool removes that asymmetry (T13 Q3). Report the stock mean of `colleagues30` weekday, C vs N.
