## Decisions

- **Rotation semantics for Step 2 (not fully spelled out by the task doc).**
  The doc says "roll the 8760 data rows by 3 ... only the row order changes."
  Read literally (reorder whole records, `hour` column included, and write
  them back in a different line order), this is mathematically a no-op for
  `step9_loadshape_aggregate.py`: it buckets and sums rows by the **value**
  in each row's own `hour` column, and summation is order-independent, so
  shuffling which line a record sits on cannot change any output — the
  detector would look "blind" even if it works perfectly. To get the
  behaviour the doc's own next paragraph expects (a genuine 3h shift in the
  reported peak), I kept the `hour` column values fixed and sequential
  exactly as in the source file, and rolled every OTHER column's values
  forward by 3 positions, so the reading that was at hour H now appears
  under hour label H+3 (mod 8760). This is implemented and comment-documented
  in `t48_helpers.py::cmd_rotate_activity` and verified against a hand-worked
  8-row example (see Verified). **Flagging for the manager to confirm this
  interpretation** — if a literal full-record reorder was actually intended,
  it would not have produced a measurable shift under either reading, so I
  judged the value-relabelling version to be what was actually meant.
- A5's "small table ... for the four archetypes" is printed at Montreal_6A
  only (matching what T45 actually measured and what `OtherDwelling__Montreal_6A`
  refers to). The full 48-row CSVs for both the published and rebuilt runs
  (`pub_a5_results.csv`, `t21_a5_results.csv`) are saved in full under `T48/`
  regardless, so nothing is lost if another city needs checking later.
- `hh_id` in the rebuilt manifest is the bare numeric id parsed out of the
  sample dirname (e.g. `sample_001_HH32811` → `32811`), matching the
  published manifest's own `hh_id` column format (plain integers, confirmed
  by `head` on the published manifest).
- `epw_path` is looked up by (cell, year) first, falling back to any row for
  that cell if no (cell, year) match exists — the published manifest's
  epw_path for a given cell appeared identical across years in the one row
  pair inspected, so this fallback should rarely if ever trigger.
