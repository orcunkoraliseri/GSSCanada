## Task

**Why.** Annual energy barely moves between years while daytime hours rise. We need the physical
explanation per end use. Wave 2 does **2022 only**: the 2030 runs are defective (WP1) and will be
re-run. This task builds and tests the machinery on 2022 so it can be re-pointed at corrected 2030.

**Input.** The Step-8 campaign, 24 cells (4 archetypes × 6 cities) × 50 households, 2022 runs only.
Local tree: `GSSCanada-main/BEM_Setup/SimResults_Step8/campaign_N50/<Arch>__<City>/sample_*/`
(~6 GB per cell, do NOT copy it all). Each run has an hourly meter CSV (find the file name by `ls` on
ONE sample dir). Use `cell_manifest.csv` in each cell to pick the 2022 runs; if two manifests exist,
record which one is current and why.
Meter rules already established (`Step8_docs/08_simulation_plots.py`, quote `file:line`): index
meters BY NAME (column order is not stable); `Electricity:Facility` already includes lights +
equipment + fans, never add them to it; `*:EnergyTransfer` columns are thermal loads, not
electricity, never add them to electricity; Jan 1 weekday rule from `reporting.py`.

**Steps.**
1. On Speed, `ls` (non-recursive, specific directories only) whether a copy of `campaign_N50` exists
   under `/speed-scratch/o_iseri/`. If yes, use it. If not, measure the size of the 2022 hourly
   meter files only (local `du` on a few samples, extrapolate). If under 20 GB, upload only those
   files (plus manifests) to `/speed-scratch/o_iseri/2J_revision/T06/input/`, keeping the directory
   structure. If over 20 GB, STOP, write the size in Verified and end the turn.
2. Script `T06_scripts/enduse_hour_2022.py`. Per household, then per archetype and stock-weighted
   using the paper's own weighting (the code weights by archetype, split equally over six cities:
   `08_simulation_plots.py:74-77,300-321`, quote what you find):
   a. annual kWh per end use: lighting, equipment, fans, `Electricity:Facility`, heating, cooling,
      water heating (thermal loads kept in a separate block);
   b. mean 24-hour profile per end use, weekday and weekend, all-year and heating/cooling season;
   c. grid-facing metrics on `Electricity:Facility`: peak demand, peak hour (circular mean),
      load factor, midday share (paper's MIDDAY window), evening ramp 14:00→17:00, hours above the
      household's own 90th percentile.
   d. closure check: lights + equipment + fans vs `Electricity:Facility`, annual, per household.
   Outputs in `/speed-scratch/o_iseri/2J_revision/T06/out/`: `enduse_annual.csv`,
   `enduse_hourly_profile.csv`, `grid_metrics.csv`, `closure.csv`, `run_meta.json` (row counts,
   households read, households skipped with reason).
3. Submit: `sbatch -p ps -c 8 --mem=32G -t 7-00:00:00` (use multiprocessing across cells up to 8).
   Write the JobID in the Ledger. **End your turn.**

**Test.** Closure (d) reproduces `Electricity:Facility` within 0.07 % (value the paper already
reports); if not, report the gap per archetype, do not tune. 1,200 households read, or the missing
ones listed.

**Not for the paper.** No figure, no prose. Numbers here are 2022 method checks.
