# `writing/Prompts/` — standing handoff prompts for the 2J paper

Prompts kept ready **before** the event they are for, so the session that handles the event does not
start from zero. Each one is written to be filled in at the top and pasted whole into a new session.

| File | Fire it when | Written |
|---|---|---|
| `2J_manager_prompt_ON_REVISION_DECISION.md` | The Building Simulation decision letter arrives — minor, major, or reject | 2026-08-07, the day of submission |

**Why they are written early.** A prompt drafted before the reviews are seen records the paper's known
weaknesses without any incentive to soften them. The same document written after a hostile review would
be shaped by it. That is the point of the folder — the revision prompt already names the parts of the
paper that are provisional, and names the one claim (the Table 1 novelty matrix) that has no defence
prepared.

**Keeping them current.** Anything that changes the submitted state — the manuscript ID arriving, the
companion 1J paper being accepted, the figures re-exported, the crosswalk count settled — should be
edited into the relevant prompt at the same time as the READMEs. A stale standing prompt is worse than
none, because it will be trusted.
