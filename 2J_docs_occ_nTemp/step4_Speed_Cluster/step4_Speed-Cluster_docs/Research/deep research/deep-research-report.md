# Q1. Piecewise-Constant (Low-Transition) Sequence Generators

- **Hierarchical Hidden Semi-Markov Model (HSMM):**  A multi-level HSMM explicitly models state durations and transitions.  For example, Dube *et al.* (2025) use a hierarchical semi-Markov “hazard” model for human activity sequences, where each segment’s duration is generated by an explicit hazard function【7†L72-L80】.  Such models enforce that once an activity (state) is entered it persists for a stochastic duration, which directly biases against spurious transitions.  They can incorporate contextual factors (e.g. demographics) into transition/hazard parameters.  Complexity is modest (a few extra parameters for duration distributions) relative to a Transformer encoder–decoder, but inference usually requires dynamic programming or structured variational inference (as in Dai *et al.*’s Stochastic Sequential Neural Network [SSNN, 2017]【72†L25-L33】).  However, by design HSMM decoders dramatically reduce fragmentation (each segment must last at least one time unit, often more).  *Example citation:* Liu *et al.* (2018) combine RNNs with HSMMs to segment time-series, modeling labels and durations as discrete latent variables【72†L25-L33】.

- **Recurrent HSMM / SSNN:**  A stochastic sequential neural network (SSNN) or Recurrent HSMM uses an RNN to generate continuous state features but imposes a discrete segmentation layer (latent change points) on top【72†L25-L33】.  The network emits an activity and a segment length for each hidden state, thus learning to “stay” in the same activity for multiple slots.  This retains the Transformer’s ability to model long-range context (via the RNN) while adding an HSMM-like mechanism for durations.  In Dai *et al.* (2017), the generative model alternates between sampling a segment duration and repeating the same label【72†L25-L33】.  This helps prevent over-fragmentation by making additional transitions costly unless strongly supported by data.  The complexity is higher than a plain Transformer (requires a segmentation inference network, e.g. Gumbel-Softmax tricks), and training is more complex (often variational EM), but it explicitly captures the piecewise-constant structure.  *Example:* Liu *et al.* (2017, ICLR) – “SSNN” – reported significant gains in segmentation tasks by modeling durations via latent segment variables【72†L25-L33】.

- **Block-Recurrent Transformer:**  In this architecture (Hutchins *et al.* 2023), the 48-slot sequence is divided into contiguous blocks (e.g. 8-hour blocks), and a Transformer layer is applied to each block sequentially in a recurrent manner【11†L49-L58】.  The model maintains a hidden state that carries information between blocks, while attending only within each block.  This enforces that context “resets” at block boundaries, which can encourage consistency within blocks (e.g. fewer state changes per block).  Block-Recurrent Transformers scale linearly with sequence length and showed improved long-range modeling in language tasks【11†L49-L58】.  Here, the inductive bias is weaker than an HSMM but still discourages rapid toggling across distant blocks.  Compared to the baseline Transformer (~30M parameters), Block-Recurrent uses similar parameter counts but reorganizes computation.  Training and inference cost are similar order, with perhaps a small overhead for managing the block recurrence.  *Citation:* Hutchins *et al.*, NeurIPS 2023 (Block-Recurrent Transformer)【11†L49-L58】.

- **SSM-based Generator (Mamba):**  Mamba (Gu & Dao 2024) is a linear-time state-space model (SSM) architecture where transition dynamics can depend on the input token【13†L52-L61】.  Although originally designed for very long sequences (up to millions of steps) in language modeling, SSMs can be adapted here by feeding a special token (or no token) and outputting the daily labels.  The “selective SSM” in Mamba learns to propagate or forget information depending on content【13†L52-L61】, effectively enabling persistence (low change) when the signal is uninformative.  This tends to produce slower variation in the output sequence.  Mamba’s cost per step is low (5× faster inference than a Transformer in Gu *et al.*’s experiments【13†L52-L61】) and it scales linearly with sequence length.  Complexity is a bit higher to implement (custom recurrent algorithms), but once implemented it can outperform same-size Transformers on long-sequence tasks【13†L52-L61】.  Its inductive bias is moderate: it does not enforce hard segmentation but the recurrent state-space tends to remember the last state over time.  *Citation:* Gu & Dao, ICML 2024 (Mamba SSM)【13†L52-L61】.

- **Semi-Markov CRF (Segmental Decoder):**  Neural sequence decoders could be coupled with a semi-Markov CRF layer on the outputs.  For example, one could design a segment-level CRF which assigns labels to contiguous spans (as in Ye & Ling 2018).  This “hybrid SCRF” would encourage that activity labels form continuous segments of learned lengths【82†L49-L57】.  In practice, one might output segment boundaries via one head and labels via another, with a CRF that scores whole-segment assignments.  This enforces consistency: e.g. it won’t score a change from “work” to “work” in adjacent slots as a transition, and discourages unlikely segment lengths.  Training such models can be done via Viterbi- or forward-backward EM.  Complexity rises (CRF inference over 48 slots is fast, but networks must output CRF features), but it hard-encodes the low-transition bias.  *Example:* Ye & Ling (ACL 2018) propose a Hybrid Semi-Markov CRF for segmentation tasks【82†L49-L57】 (though not generative, it shows segment-level decoding works).

# Q2. Alternative Conditional Discrete Generative Models

- **Discrete Diffusion Models (D3PM):**  D3PMs (Austin *et al.* 2022) extend diffusion to categorical sequences via a learned noise kernel【34†L53-L62】.  Instead of autoregressively generating one slot at a time, D3PM corrupts an entire diary at varying noise levels and learns to denoise.  This can capture multimodal output distributions better than MLE.  (a) With noisy K-NN targets, diffusion’s iterative denoising may be robust to label uncertainty since learning smooths out noise across timesteps.  (b) Multitask outputs: One can use a shared diffusion model that outputs all three heads jointly (e.g. a  `"vocabulary"` of (activity,home,presence) tuples).  (c) Inference is expensive: ~100–1000 denoising steps per diary.  (d) Hard constraints: not built-in, though one could design an absorbing state or penalty in the diffusion process to discourage inconsistent outputs【34†L53-L62】.  Overall, D3PM provides strong distribution matching (it achieved state-of-art on discrete text【34†L53-L62】), but at ~10–100× slower inference than autoregressive decoding.

- **Score-Entropy Discrete Diffusion (SEDD):**  SEDD (Lou *et al.* 2024) is a discrete diffusion model trained with a novel “score entropy” loss【38†L19-L28】.  It was shown to outperform previous diffusion LMs and even approach AR models in perplexity【38†L19-L28】.  (a) Noisy labels: SEDD’s denoising objective might better tolerate conflicting targets, since the loss is formulated on score distributions rather than exact labels.  (b) Multi-task: SEDD could in principle condition on demographics and output a joint discrete pattern, similar to D3PM. (c) Inference: still sequential (many steps). (d) Consistency: As with any diffusion model, no hard enforcement, but one could incorporate a joint score for consistency.  SEDD is complex to implement (score-matching objective) and slower at inference, but could better match complex marginal statistics due to its mode-covering behavior【38†L19-L28】.

- **Masked Diffusion (MDLM/MD4):**  Recent works (MaskGIT, MDLM, MD4) train diffusion models that iteratively “unmask” slots in any order【40†L69-L77】【42†L372-L380】.  For example, MDLM (NeurIPS 2024) uses a mixture of masked-MLM losses to train a parallel decoder【75†L69-L73】.  (a) Noisy targets: Masked diffusion can be trained with expected targets (soft or average KNN labels), possibly smoothing noise via masking.  (b) Multi-head: The model can emit multi-hot masks for all outputs at each step, since predictions are parallel.  (c) Inference: still iterative (though often <10 steps via smart scheduling), faster than D3PM but slower than AR.  (d) Consistency: Hard to enforce; one could embed consistency logic in the mask ordering or constrain mask patterns.  MDLM showed that, with good training recipes, masked diffusion nearly matched AR likelihoods【75†L69-L73】.  Its major downside is inference cost (multiple mask-scheduling passes) and complexity of implementation (schedule design).

- **Discrete Flow Matching:**  Discrete Flow Matching (DFM) (Gat *et al.* 2024) is a recent “flow” paradigm for categorical data【76†L59-L67】.  It parameterizes a continuous-time “flow” that transports a simple prior to the target discrete distribution.  (a) Noisy labels: DFM trains by matching distributions, so it can potentially average over inconsistent targets.  (b) Multi-task: One can model the joint space of (activity,home,presence) as the discrete domain.  (c) Inference: sampling from flows can be parallel (via an ODE solver) but may require many function evaluations (like diffusion).  (d) Consistency: As with diffusion, no hard rules, but probability paths might be chosen to favor consistent combinations (e.g. penalize paths leading to disallowed states).  Gat *et al.* report that DFM improves perplexity over previous diffusion approaches【76†L59-L67】.  However, DFM is novel and complex, and implementing it for multi-task diaries would be nontrivial.

- **Energy-Based Models (EBMs):**  EBMs assign an unnormalized energy to each whole-diary output configuration.  The model can include terms penalizing inconsistency (e.g. add +∞ energy if “sleep” while away from home).  (a) Noise: EBMs can potentially learn to ignore conflicting targets by energy shaping. (b) Multi-task: a joint energy naturally handles multi-head outputs. (c) Inference: sampling from EBMs is very expensive (MCMC or Langevin steps per diary). (d) Hard constraints: straightforward by adding infinite-energy constraints.  In practice, training EBMs on high-dimensional discrete data is difficult (many recent works focus on continuous data).  EBMs offer the most direct way to enforce constraints, but are typically costly and unstable. (No concrete citation, but see general EBM tutorials like LeCun *et al.* 2006).

# Q3. Noise-Robust Training for Contradictory Soft Labels

- **Robust Loss Functions:**  Use classification losses that mitigate label noise.  For example, *Symmetric Cross-Entropy* (SCE, Wang *et al.* 2019) or *Generalized Cross-Entropy* (GCE, Zhang & Sabuncu 2018) combine cross-entropy with mean absolute error to soften extremes.  In a multi-class or multi-label context, one could similarly soften the binary heads (e.g. by reweighting targets).  Another strategy is *bootstrapping loss* (Reed *et al.* 2015): train on a convex combination of model predictions and noisy labels, which tends to ignore inconsistent target values.  These losses require no special model changes and can be plugged into sequence training, but they are still pointwise (per-slot) and may not fully correct highly contradictory sequences.

- **Latent True-Label Models (EM):**  Assume each diary has a latent “true” sequence, and the K-NN targets are noisy observations.  One could frame this as an EM problem: E-step infers the latent sequence distribution given the model and observed KNN diaries, M-step trains the model to match these inferred latents.  For example, a latent variable model (e.g. an HSMM) could be fit to each neighborhood to estimate a consensus diary, then train to that.  This resembles “data distillation.”  It adds complexity (extra inference loop) but directly addresses instance-dependent noise.  No obvious off-the-shelf reference, but conceptually similar to noisy-channel sequence EM or hidden Markov smoothing.

- **Distribution-Matching Losses:**  Instead of per-slot loss, use batch-level objectives to match target distributions.  One can incorporate a Maximum Mean Discrepancy (MMD) or Sinkhorn distance between the distribution of model-generated diaries and the empirical distribution of KNN targets (or holdout).  For example, penalize discrepancies in histograms of activity counts, at-home rates, etc.  This aligns with the stated goal (matching population marginals) and can be robust to label noise by focusing on aggregated statistics.  MMD was used in GAN-like generative training (Li *et al.*, NeurIPS 2015) and Sinkhorn (Cuturi 2013) is an entropy-regularized optimal transport distance.  These losses operate on sets of sequences, so they require drawing batches of generated diaries per demographic group.  The drawback is that they can be unstable or require large batches, but they directly enforce the desired distributional metrics (e.g. matching transition counts or marginals).

- **Adversarial/Divergence Objectives:**  A generative adversarial (GAN) or flow-loss approach could be used.  For example, training a discriminator to distinguish real vs. generated diaries encourages matching the *joint* distribution, potentially tolerating label noise.  Alternatively, loss functions that interpolate between KL and JS (e.g. $\alpha$-divergences) can trade off mode-covering versus mode-seeking behavior.  For instance, an $\alpha$-Divergence with $\alpha>1$ is more robust to outliers (like noisy labels), whereas KL ($\alpha \to 1$) is mode-seeking.  Choosing an $\alpha<1$ makes the model cover all modes of the (noisy) target distribution.  These methods require careful tuning and often add complexity (discriminators or custom losses), but they directly attempt to align generated and observed diary distributions beyond per-slot CE.

# Q4. Multi-Head Consistency Enforcement

- **Semantic Probabilistic Layer (Neuro-Symbolic SPL):**  This is a neural module that enforces hard logical constraints on outputs【55†L25-L33】.  For diary generation, one could add an SPL at the final layer that projects the raw decoder logits into a joint distribution over (activity, at-home, co-presence) that only assigns nonzero probability to logically consistent tuples【55†L25-L33】.  For example, the SPL could implement the rule “if activity=‘sleep’, then at-home=1 and copresence is {alone,spouse}.”  This guarantees zero probability of illegal combinations, satisfying all constraints by construction.  The downside is computational: SPLs perform exact inference (weighted model counting) under the constraints, which may be expensive for 48 time steps and 10×1×9 possible states each.  But since the constraints are simple, a specialized CRF-like or rule-based layer may suffice.  SPLs have been shown to integrate smoothly with backprop and improve structured tasks (Ahmed *et al.*, NeurIPS 2022)【55†L25-L33】.

- **Constrained Decoding / Beam Search:**  Instead of modifying training, enforce consistency at generation time.  For example, use constrained beam search so that any partial diary violating a constraint is pruned.  This requires hand-coding all logical rules (e.g. work→at-home=0).  It is compatible with any autoregressive or masked decoder.  Complexity depends on rule checking per step (cheap here).  However, if the model never learned the pattern (weekday vs weekend), constrained decoding can only enforce hard facts, not distributional orderings.  This technique adds little model cost but relies on exact knowledge of constraints.  (No citation, but see e.g. constrained generation methods in NLP such as Hokamp & Liu (ACL 2017) for lexically constrained decoding.)

- **Product-of-Experts Decoding:**  View each head (activity, at-home, copresence) as an “expert” providing a probability distribution.  Multiply them (and renormalize) to get a joint output distribution.  For example, if the activity head says “work with prob 0.7,” and the at-home head says “at-home=0 with prob 0.9,” one forms p(activity=work ∧ at-home=0) ∝ 0.7*0.9.  To enforce logic, the copresence head’s probabilities for channels incompatible with at-home=0 can be masked out.  This is essentially a factorized joint model with hard mask: p(a,h,c) ∝ p(a)*p(h)*p(c)*I(consistency(a,h,c)).  It’s fast at inference (just multiply scores) and introduces no extra parameters.  Training the heads independently but decoding jointly (PoE) may sacrifice some likelihood fit, but it ensures consistency by design if you zero out illegal joint states.  Compatibility: works with any decoder (AR or diffusion) because the final combination is external.  *Reference concept:* PoE was introduced by Hinton (2002) and has been used in multimodal fusion, though rarely for enforcing logical constraints.

- **Factorized Joint Architecture:**  Design the model so that one output deterministically sets another.  E.g. use a classifier p(activity) and a learned function “home= is_at_home(activity,demographics)”.  For instance, implement a small rule network inside the model that sets at-home=0 whenever activity is in {work,travel,education} and at-home=1 for {sleep,eat (maybe half?), other inside}.  This hard-codes most logical relationships.  The neural decoder then only generates the activity sequence (and maybe one other head) and deterministically derives the rest.  This is very fast and foolproof, but it throws away modeling flexibility (the model can’t learn, e.g., someone working from home unless rules allow it).  It’s easily compatible with any decoder (just output the rule-based head values at inference).  No recent paper exactly, but it is a common engineering hack in structured generation (e.g., parsing tasks often predict spans then deterministically fill features).

# Q5. Conditioning & Demographic Integration

- **FiLM Conditioning:**  Feature-wise Linear Modulation (FiLM, Perez *et al.* 2018【60†L54-L63】) applies learned affine transforms to decoder features based on the demographic input.  Concretely, each decoder layer’s activations are scaled and shifted by vectors computed from the demographics.  This allows rich modulation (the condition can gate or rescale each feature channel dynamically).  FiLM is lightweight (just 2 linear layers per decoder layer) and scales to 150k users easily.  It can adapt to stratification: different age/sex combos produce different FiLM parameters.  FiLM has been shown to effectively inject context in vision and language tasks【60†L54-L63】.  It directly forces all decoder layers to see demographics, likely fixing the weekday/weekend effect.  Inference cost is minimal (extra linear ops).  Risk: if the model is too reliant on FiLM, it might not generalize when demography patterns shift; but since FiLM is learned end-to-end, it can adapt to actual data shift if included in training.  *Citation:* Perez *et al.*, AAAI 2018【60†L54-L63】.

- **Cross-Attention from a Demographic Encoder:**  Instead of simple concatenation, encode the demographics (e.g. one-hot or continuous features) into a learned “demographic memory” vector or sequence, and let the decoder attend to it at each time step (like in encoder–decoder).  This is akin to prefix- or context-based generation.  It allows flexible interaction: different slots can focus on different parts of demographics.  Complexity: a small encoder for demographics (negligible) and extra cross-attention layers.  This scales well (only 12 strata, so memory is tiny).  It can capture interactions (e.g. older persons with kids in household).  In practice, this is similar to FiLM but potentially more expressive.  If the model under-uses day-stratum (weekday/weekend), an attention mechanism might highlight it more strongly at relevant slots.  Inference overhead is minimal per slot (one attention query over 10-20 “demographic tokens”).  No hard guarantee, but it often works well in condition-based generation (see e.g. Vu *et al.* 2019 on cross-attentive conditional decoding).

- **Hypernetwork / Conditional Parameter Generation:**  A hypernetwork (Ha *et al.* 2016) generates part of the decoder weights from the demographic vector.  For example, a small network takes age/household features and outputs (say) the weights of one or two Transformer layers.  This allows each demographic group to have slightly different model parameters.  Complexity is high: the hypernet must output large weight matrices (unless you restrict it to a subset), which can be memory-intensive.  Inference cost is also higher (compute hypernet output once per instance).  On the plus side, it can in principle adapt the entire dynamics of the model per cohort.  A variant is **Adaptive LayerNorm** (Dumoulin & Perez 2018), where the layer-norm scale/bias depend on context.  However, hypernetworks can overfit if cohorts are few (12 cells only) and may not generalize to new cycles (though the survey-cycle input could drive the hypernet).

- **Mixture-of-Experts (MoE) Gating by Stratum:**  Implement a mixture-of-experts Transformer decoder (Shazeer *et al.* 2017).  For example, have one expert network per cycle or (cycle×stratum) cell, and a gating network selects or interpolates experts based on the demographic.  This fully isolates knowledge per subgroup.  Complexity: large, since you need 12 separate decoders (though sparsely used if switch).  Inference can be efficient if gating is sparse (only route through 1-2 experts).  However, with only 12 cells, you risk having too few examples per expert if splits fine-grained.  On the other hand, MoE can handle distribution shifts by dedicating an expert to post-COVID patterns (2022 vs earlier).  Risk: training instability (MoEs are known to require load balancing and lots of data) and lumpy resource usage.  This approach scales in theory (Switch Transformers scaled to thousands of experts on massive hardware), but our data (150k diaries) is too small for many experts.  Possibly a simpler dense MoE (each head is weighted combination of experts) could be tried.  *Citation concept:* Fedus *et al.* (ICLR 2022) discuss gating and sparsity in MoEs, though not specifically demography.

- **Prefix Tuning per Stratum:**  Prefix-tuning (Li & Liang 2021) keeps the model fixed and prepends a trainable sequence of “virtual tokens” per condition【77†L12-L21】.  Here, learn a small prefix for each (cycle×stratum) combination (12 tokens for each of 12 cells).  At generation time, the decoder attends to the prefix as if it were context.  This is very parameter-efficient (only 12×embedding dims).  It allows the model to adapt in a narrow way to each cell, and it was shown to work well in practice【77†L12-L21】.  Complexity: tiny.  It can effectively shift the model’s behavior across cells, preserving any learned differences.  It scales easily (just a small embedding table).  Since prefix tuning was developed for NLP tasks of similar size, it should handle 150k respondents.  It also allows handling distribution shift: if 2022 diaries differ, those prefixes will adapt to model them.  *Citation:* Li & Liang, ACL 2021【77†L12-L21】.

# Q6. Time-of-Day Inductive Bias

- **Periodic (Fourier) Positional Encoding:**  Incorporate time-of-day into the slot positions.  For example, instead of a linear 1–48 positional encoding, use a 24-hour (periodic) encoding: $\sin(\omega t)$ with $\omega=2\pi/48$.  Or use **Time2Vec** (Kazemi *et al.* 2019) embeddings that learn periodic functions of the half-hour index.  This explicitly tells the model that slot 1 (midnight) and slot 49 (next midnight) are equivalent, etc.  It biases the model to treat the sequence as circular daily data.  In practice, one could add 2–3 Fourier features (cos,sin of $\frac{2\pi \times \text{hour}}{24}$) or learn embeddings for “hour-of-day” and “weekday/weekend”.  Complexity is minimal (a few fixed features), but it can dramatically improve diurnal pattern learning (see studies in time-series forecasting).

- **Learned Time Embeddings:**  Assign a distinct embedding to each slot (1–48) or each hour, perhaps tied across days.  This is like positional encoding but learned.  One can further add a “temperature” factor modulated by circadian (e.g. more importance near common transition times).  Alternatively, use **relative positional encodings** that emphasize shorter distances at boundaries (morning vs midnight).  These encourage the model to treat certain times similarly (e.g. morning hours all “morning”).  Learned encodings add parameters (48 vectors), but negligible cost.  They require enough data to learn stable patterns, but 150k diaries should suffice.  They directly give the model clues about time (e.g. sleep usually occurs in late-night slots).

- **Hierarchical Decoder (Coarse-to-Fine):**  First generate a coarse schedule (e.g. 4 blocks: sleep, work, leisure, other) over the 24h, then refine each block into 30-min slots.  For example, a low-resolution decoder could pick the start/end times of “sleep” and “work” segments (like 4 turns in the day), and a second-level decoder fills in the fine activities conditional on these segments.  This is akin to a **segmental VAE** or multi-scale RNN (Chung *et al.* 2016).  It strongly biases against fragmentation by construction (you first commit to long blocks).  Complexity: two-stage model (maybe two Transformers).  Training requires supervising the coarse segments (could use heuristic: e.g. label contiguous same-activity runs).  It can capture day structure explicitly.  Risk: if the coarse stage is wrong, the refined sequence is forced to fit it (e.g. if it misses a short nap segment).  But this mirrors how humans plan days (identify major blocks then detail).  No single paper citation, but many hierarchical generation models exist (e.g. Hu *et al.* 2018 “MoSED” coarse-to-fine summarization; conceptually similar).

- **Time-Gated Attention:**  Use mechanisms that adapt based on time context.  For instance, at midnight transition the decoder could reset some memory.  One could use a *clocked* RNN/Transformer (like Salakhutdinov’s Clockwork RNN idea) where certain layers update only at coarser time scales (sleep vs awake phases).  Or include explicit “time since last activity” features.  These ideas impose prior that behavior changes more at specific times.  Complexity varies; often just gating some weights by a “slot-of-day” feature.  No specific citation, but time-aware transformers (e.g. Zhao *et al.* 2021) show improvements on time-series when using such biases.

# Synthesis & Shortlist of 10 Candidates

Below are **10 top candidate architectures** (drawn from Q1–Q6) ranked by expected fit.  For each we give: **relative training/inference time** vs the baseline Transformer, **biggest risk**, and **key metric likely to improve**:

- **Hierarchical HSMM Decoder:**  (*Wall-clock:* ~2× baseline due to dynamic-programming inference; *Risk:* model complexity/inference difficulty, possibly over-smoothing; *Metric:* activity-transition count – should drop fragmentation significantly.)  
- **Stochastic SSNN (Recurrent HSMM):**  (*Time:* ~2× training, similar inference cost if amortized; *Risk:* training stability, variance in latent inference; *Metric:* at-home & co-presence marginals – better segment-level consistency.)  
- **Block-Recurrent Transformer:**  (*Time:* ~1× (slight overhead for recurrence) with linear scaling; *Risk:* might still learn small-scale fragmentation; *Metric:* long-run metrics (JS divergence across 48 slots) – could improve global sequence coherence.)  
- **Mamba (State-Space SSM):**  (*Time:* ~0.5–1× (faster inference than baseline); *Risk:* lack of proven batch training for structured output; *Metric:* log-likelihood and transition count – expected fewer false transitions due to SSM memory.)  
- **Discrete D3PM Diffusion Model:**  (*Time:* ~10–20× slower at inference (100+ steps); *Risk:* slow decoding, potential mismatch in multi-head output design; *Metric:* full-distribution metrics (marginal activity JS, co-presence rates) – diffusion tends to match global stats well.)  
- **Masked Diffusion (MDLM/MD4):**  (*Time:* ~5–10× slower (fewer steps than D3PM); *Risk:* inference speed and consistency enforcement; *Metric:* similar to D3PM – should cover multiple plausible diaries and improve marginal matching.)  
- **Discrete Flow Matching (DFM):**  (*Time:* ~10× (ODE solver or many evaluations); *Risk:* novelty – hard to adapt quickly, risk of implementation bug; *Metric:* coding-behavior of transitions – reported better perplexity, likely similar benefits as diffusion.)  
- **Semantic Probabilistic Layer (SPL):**  (*Time:* ~1× inference (small overhead for logic), modest training overhead; *Risk:* constraint set completeness (missing some logic) or slowing; *Metric:* multi-head consistency rate – should achieve 100% logical consistency by design.)  
- **FiLM Conditioning:**  (*Time:* ~1× (lightweight adds); *Risk:* might under-fit if model ignores conditioning or demographics covariate shifts; *Metric:* stratified at-home differences (weekday vs weekend ordering) – should sharpen demographic signal usage.)  
- **Prefix Tuning per Stratum:**  (*Time:* ~1× (prefix is tiny); *Risk:* limited adaptability if fixed prefix tokens per cell, though can be fine-tuned; *Metric:* variance of at-home rates across cells – prefix allows per-cell bias adjustment, expected to reduce marginals error.)  

Each of these should be prototyped on a 5% stratified subset.  We expect the **fastest** are FiLM, prefix tuning, and SPL (nearly baseline speed), while the generative diffusion/flow methods and hierarchical models cost more. The **biggest risks** include training complexity (HSMM/SSNN), inference speed (diffusion/flow), and over/under-fitting of conditioning (FiLM, prefix).  Most likely improvements: HSMM-based models will cut down transition count first, diffusion will improve JS divergence of activity marginals, and SPL will eliminate logical inconsistencies immediately.
