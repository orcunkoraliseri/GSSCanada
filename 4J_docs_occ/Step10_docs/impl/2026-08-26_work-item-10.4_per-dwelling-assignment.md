## The conservation clause, stated before any code

`§9`, and this is the whole point of the item:

> The annual mean of `φ_int` is exactly `3.0 W/m²` **per zone** *and* **per building** at every `f`,
> asserted on the **emitted CSV on disk**, with the numeric bound derived from the write format —
> not asserted in the generator.

🔴 **`FINDING 132` is this exact failure one level up:** the pre-registered conservation held in the
generator and not in the artefact — `4.01e-07` relative at `%.6f`. With `N_u` series it can now fail
**per zone while the building mean is right**, which is the new failure mode `G10.13` exists for.

**Per building is AREA-WEIGHTED.** `φ_int` is W/m², so the building mean is
`Σ(A_z · mean φ_z) / Σ A_z`. ⚪ With equal zone areas the weighting is trivially satisfied, so a
perturbation with **unequal** areas is mandatory or the arm is vacuous — the `FINDING 95` /
`FINDING 127` discipline.

---

## Decisions this task had to take, and what they were

1. **Zone areas are `footprint_area_m2 / zone_count` unless the table carries per-zone areas.**
   🔴 **Declared as an ASSUMPTION, not a measurement** — the real per-zone areas arrive with the
   dwelling layout. Recorded here rather than buried, because equal areas are exactly the case that
   makes the area-weighted arm of `G10.13` look green for the wrong reason.
2. **Arm from `zone_source`, never from `zone_count`.** `EUROPEAN_DWELLING_LAYOUT` → **Arm D**;
   `FALLBACK_ONE_ZONE_PER_FLOOR` → **Arm F**. A building with `zone_count = 4` from the fallback is
   four *storeys*, not four dwellings, and assigning it four independent diaries would manufacture
   the very diversity `H10` is testing for.
3. **Arm F gets ONE diary for the whole building**, repeated across its storey zones. The fallback
   spatially averages non-coincident gains by construction (`G10.22`), so pretending each storey is
   an independent household would hide the bias the arm is a lower bound because of.
4. **Country → fold is identity** (`ES → es`, `GB → uk`, `IT → it`): a cell's schedules come from the
   fold that held its country out (decision 11 / `G8.16`). Read from the bundle's **own
   `manifest.json`**, never from a filename.
5. **`WRITE_DECIMALS = 10`**, matching work item 8.5, so the bound is `0.5e-10` and the
   `FINDING 132` residue at `%.6f` cannot recur silently.

## 🔴 THREE DEFECTS THE BATTERY FOUND IN THIS FILE'S OWN FIRST DRAFT

1. **`G10.8` returned PASS on an EMPTY population.** The first `force_fold` perturbation pointed every
   dwelling at a fold with no pool, so every building was skipped, **zero** dwellings were assigned,
   and the gate read *0 unlocatable, 0 wrong-fold* → **PASS**. 🔴 **A gate whose population is empty
   has not been satisfied, it has not been asked.** `FINDING 95` / `FINDING 127` again. Both `G10.8`
   and `G10.13` now return **`NOT_EVALUABLE`** on an empty input. **The MISS is what found it.**
2. **The perturbation itself was badly designed** — it *removed* the gate instead of testing it.
   Replaced by `mislabel_fold`: the diary really is drawn from the right fold, and the dwelling
   **records a different one**. A genuine cross-fold drive, and it fells `G10.8`.
3. **Globbing `Step7_docs/outputs_step7/schedules/` picked up the wrong bundles.** That directory
   also holds `leg4_*`, the `_cal<year>` survey-calendar variants and seven `perturb_*` bundles built
   to be malformed; `perturb_hours_8759` has 8,759 values and **the reader refused it**, which is why
   nothing silently emitted a short year. 🔴 **A manifest filter alone is not enough either** —
   `perturb_null`'s manifest is indistinguishable from a production one, because the null
   perturbation *is* "change nothing". The authority is now the **campaign's own `schedule_bundles`
   field**, the artefact `G8.16` traces, with the manifest check as a second opinion.
