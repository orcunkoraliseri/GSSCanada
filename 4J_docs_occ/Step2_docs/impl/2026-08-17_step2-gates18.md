## Decisions
1. **Ran locally, not via `sbatch`.** The task doc's CLUSTER RULES describe how to run on Speed if
   running there; nothing in the task doc forbids a local run when the data and environment already
   exist locally and the job is small (2M rows, 18MB). This avoids the exact "submit and wait" pattern
   the NO PARKING section exists to prevent — there was nothing to wait for. Flagged for the manager to
   confirm this reading is correct; if not, the same command re-runs unchanged via `sbatch` on Speed.
2. **`--selftest` was NOT extended with `strat_*` columns / synthetic `crosswalk_strata.csv` rows.**
   The task's deliverable is the real battery against the already-accepted, already-built
   `harmonised.parquet` and `crosswalk_strata.csv` (D-S2-18/D-S2-19's Task B outcome), which is what
   `--perturbation all` exercises directly. `--selftest`'s synthetic fixture builder
   (`build_synthetic_country`/`build_fixtures`) still produces the original 16-gate schema only; under
   `--selftest`, `G2.17` will always report a missing-column FAIL (no `strat_*` columns in the synthetic
   parquet) while `G2.18`/`V2.j` still read the REAL `crosswalk_strata.csv` from the default
   `Step2_docs/outputs_step2` directory and are meaningful. Documented in the script's own `--selftest`
   help text. Not extending it was a scope call to avoid a second, parallel synthetic-fixture build for
   a battery whose real subject already exists and is the round's whole point.
3. **G2.17(a)/(b) scoped to the five HARMONISED `strat_*` columns only** (`STRATA_COLUMNS`), not the six
   `_raw` carriers. Rationale: D-S2-18's own argument is that the *prefix* (which never includes the
   raw columns) cannot serialise a null design stratum; the raw columns carry the literal national
   value, which can legitimately be missing/blank pre-banding. The val doc's G2.17 row says "shipped
   `strat_*` column" without naming the raw carriers explicitly, and the whole D-S2-18 motivation is
   about the *prefix*.
4. **G2.18(a)'s escalation clause uses the literal reading "smallest share among the other two"
   INCLUDING zero, with no filtering.** This is what actually reproduces D-S2-19's own claim that the
   clause "fires by design on strat_econ_status (ES 0.0%, UK 6.3%, IT 13.5%)" — under a
   filter-zero-then-skip reading (the convention `G2.11`'s *different-direction* escalation uses), none
   of the three countries' pairwise comparisons clear the 10x bar and the clause would never fire,
   contradicting the val doc's own stated expectation. Confirmed against the shipped numbers before
   writing the gate. Consequence: this same literal reading will also escalate `strat_hh_type` (ES 0.0%,
   IT 0.0%, UK 3.6%) — the val doc names only `strat_econ_status` as the worked example, doesn't deny
   `strat_hh_type` also escalates, and both are reported, not silenced, per D-S2-19's own instruction.
5. **G2.18(a) is *expected* to report FAIL on real data**, independent of any perturbation, because of
   the escalation clause above. This is a pre-registered, expected-by-design result per D-S2-19's own
   text ("this fires ... and is reported, not silenced"), not a defect in the crosswalk or the gate.
   Because of this, whole-gate PASS/FAIL cannot be used to tell whether the two new perturbations that
   target `G2.18` actually fired their own specific defect — see the M-7 sub-clause `counter`
   mechanism added to the runner (`subclause_counter()`, acceptance tests 2b/3b) for the field-level
   check that is actually authoritative for firing/clean verdicts on `G2.17`/`G2.18`.
6. **Perturbation `italy_age_band_split` retargets Italy's source `04` to an already-3-country-declared
   band (`15-24`, or `25-34` if `04` already targets `15-24`)**, not a novel band, so it isolates
   `G2.18 (b)` without also tripping `G2.18 (a)`'s leak count as an unintended side effect.
7. **Perturbation `null_strat_econ_status` nulls a whole diary's value**, not one row, because
   `strat_*` is a per-person-day constant (D-S2-18); nulling one row only would itself trip `G2.17 (b)`
   (non-constant group) as well as `(a)`, conflating the two sub-clauses the val doc keeps deliberately
   separate.
