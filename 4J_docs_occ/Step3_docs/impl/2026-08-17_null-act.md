## Decisions
- **Part 2 bucket definition, `raw_null`**: `act_raw` is null (`pd.isna`) OR (a string that, after
  `.strip()`, is empty). The task doc's own wording ("null / blank / empty") does not distinguish a
  literal-empty-string act_raw from a whitespace-only one; both are folded into `raw_null`, matching
  the spirit of `4thJ_harmonise_step2.py`'s own `act2_raw` three-state handling (`is_null_a2` /
  `is_blank_a2`), which the task doc did not ask to be reproduced exactly for `act`/`act_raw` (no
  three-state split was requested -- the task doc's own table collapses null+blank+empty into one
  `raw_null` bucket).
- **`raw_column_absent`**: interpreted as "act_raw is non-null nowhere in this country's rows at
  all" (checked against ALL of that country's rows, not just the null-act subset), since the task
  doc's own wording is "the country ships no act_raw at all." Not expected to fire (act_raw is a
  retained raw column for all three countries per `tools/4thJ_harmonise_step2.py`'s
  `BASE_COLUMNS_TAIL`), but checked live, not assumed.
- **Crosswalk read**: `dtype=str, keep_default_na=False`, matching `4thJ_harmonise_step2.py`'s own
  `load_crosswalks()` convention exactly (not `gates_step2.py`'s `keep_default_na=True` variant),
  because the goal is to reproduce how the actual Step 2 join saw the crosswalk, not a gate's
  separate convention.
- **Part 3 run-mask ambiguity, resolved and documented in-script**: the task doc says "for the
  raw_null rows only ... classify every maximal run of consecutive null-`act` episodes." Taken
  literally, the run-defining mask is `raw_null` itself (not "act is null" generally), which means a
  run's neighbour can be a World B (`raw_present_unmapped`) episode -- whose `act` is ALSO null, so
  it cannot be used for the interior agree/disagree comparison the way `4thJ_null_structure.py`'s
  precedent assumed (that script's mask and comparison field were the same field, so a neighbour was
  always guaranteed non-null). Handled by adding a sixth bucket, `interior_worldB_adjacent`, for any
  raw_null run bounded on either side by a null-`act` (World B) neighbour, instead of crashing or
  silently comparing NA==NA. This bucket is expected to be non-empty only if World B is non-empty.
- **Minutes-share and per-diary minutes distribution** (task doc, end of Part 3): computed for ALL
  null-`act` episodes (World A + World B combined), not raw_null only, because the cited reason
  (`G3.2` requires `sum(DUR)==1440`) is threatened by any null-act episode regardless of which world
  it belongs to. A raw_null-only column is printed alongside it for completeness. The task doc does
  not explicitly say which population this covers; this is the assumption taken.
- **Part 5 sentinel check** is global (all three countries' rows in `crosswalk_activity.csv`
  combined), not per-country, matching the task doc's phrasing ("appears as a legal target code in
  crosswalk_activity.csv" / "appears as a value in the act column") which does not ask for a
  per-country breakdown here (unlike Parts 1-4).
- **Top-30 `act_raw` cross-check defect labelling**: two categories only, per the task doc's own
  two-way split ("absent from the crosswalk entirely" or "present but mapping to a null target").
  A third, unexpected label (`present_maps_to_...`) is emitted only as a defensive branch if a value
  the loader itself classified as unmapped turns out to actually be joinable -- which would indicate
  a bug in this script's own bucketing, not a real data state, and is printed rather than silently
  dropped.
