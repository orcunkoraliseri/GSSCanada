## Decisions taken here, and why

1. **Per-fold temperature, never a shared one.** A single global T would be chosen partly on Spanish
   validation diaries, and Spain is the held-out country on fold `es`. That is contamination by the
   same argument `G5.6i` scores. Three folds, three models, three temperatures. Not a preference —
   the alternative is inadmissible.
2. **Paired design.** 600 prompts drawn ONCE with `TH.SEED` and reused at every grid point; the
   reference is those same 600 real diaries. An unpaired draw puts sampling noise between the curve
   and the knob.
3. **Metrics are IMPORTED from `4thJ_step4_train`**, not reimplemented: `activity_entropy_nats`,
   `split_prefix_body`, `parse_episodes`. Step 4 already prints this entropy at every checkpoint
   (`entropy=3.282` on `es` epoch 0), so the numbers have to be comparable. Only the generation loop
   is local, because temperature is the one thing that must differ.
4. **Fidelity = the 144-slot at-home profile MAE (pp)**, with activity-share TVD (pp) reported
   beside it. Chosen for continuity: `TH.G4_1_STATISTIC` is `at_home_share` and Step 6 scores the
   same time-of-day family. Item 5.4 never defined "fidelity metrics"; this is the definition, and
   it is written down before the first curve was seen.
5. **No diary weights.** `weight_dia_cal` (FINDING 53) re-bases the real population onto the
   calendar week; that changes which population the reference is, not what the decoding knob does,
   and the design is paired against the drawn diaries. Stated, not silently omitted.

### 🔴 `FINDING 66` — THE GENERATION RNG IS NEVER SEEDED, AND THE JSON SAYS `seed: 42` ANYWAY

`generate_at` calls `model.generate(..., do_sample=True)` with **no `torch.manual_seed` anywhere in
the file** (`grep -n seed` returns four hits, all the prompt draw). The sampling RNG is torch's
default state, advancing across the whole run, so:

* the single realisation at each grid point **is not reproducible**, not even by re-running the
  same script on the same node; and
* the artefact writes `'seed': SEED` into `temperature_calibration_<fold>.json` beside the curve,
  where a reader will take it to mean the curve is seeded. It scopes the prompt draw only.

This compounds `FINDING 65` rather than duplicating it: even if somebody argued one realisation
were enough, that realisation cannot be reproduced or re-derived. And it means the current run
cannot be counted as seed #1 of five — the five must be *distinguishable by seed*, and this one has
no seed.

Additive fix when it is fixed: `torch.manual_seed(s)` immediately before each `generate_at`, `s`
recorded per row; rename the existing JSON key to `prompt_seed`. **Not applied — the jobs are
running and the script on Speed must not move under them.**
