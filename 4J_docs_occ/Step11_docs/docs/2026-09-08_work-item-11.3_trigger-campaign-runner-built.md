## 2. 🔴 THE SEAM WITH STEP 10 — WHAT `G11.15` IS ACTUALLY GUARDING, MEASURED

Read out of `openubem/semantic/european_schedules.py`, not assumed. `build_step8_gain_series`:

```python
    values = BASE_GAIN_W_M2 * ((1.0 - sensitivity_f) + sensitivity_f * (values / annual_mean))
    ...
    if not np.isclose(float(values.mean()), BASE_GAIN_W_M2, rtol=1e-8, atol=1e-10):
        raise AssertionError("Step 8 annual gain conservation failed")
```

and the object it attaches is a single `OTHEREQUIPMENT`, `Fuel_Type=Electricity`,
`EndUse_Subcategory="EU_Step8_InternalGains"`, `Watts/Area = 1.0`.

🔴 **So the `C2` cell carries ONE LUMPED internal-gain term — occupants, appliances and lighting
together — as its INPUT, and produces SPACE HEATING as its result. `f` REDISTRIBUTES that gain in
time and never rescales it; the annual mean is conserved and the code asserts its own conservation.**

That settles the accounting rule item 11.4 needs, and `S10` encodes it:

| path | end-uses |
|---|---|
| Step 10 `C2` | `space_heating` |
| Step 11 `11.3` | `appliance_electricity`, `dhw` |

🔴 **Step 11's appliance electricity MUST NEVER be injected back into a Step 10 heating model. That
heat is ALREADY inside the conserved `BASE_GAIN_W_M2`, and adding it again is exactly the double
count `G11.15` names — invisible in either artefact read alone.**

⚪ **A consequence worth writing down before somebody claims otherwise: because the annual mean is
conserved, a flat's appliance MAGNITUDE has no path into its heating number at all. Only the TIMING
crosses the seam.** Any Step 11 sentence implying that dwelling-specific appliance loads changed a
Step 10 heating result is false.

## 3. 🔴 THE FINDING THAT CHANGES WHAT SECTION 1.1 MAY CLAIM — ONE HUNDRED DIARIES, NOT ONE THOUSAND

Spec §1.1 says Step 11 *"is the first configuration in this project that sits inside the range the
source models were validated in"* — 100–500 dwellings — because Step 10's neighbourhoods carry
~1,200 buildings each.

**Measured here:** `4thJ_step10_assign.step7_index()` indexes **exactly 100 presence schedules per
fold** (`es` 100 / `uk` 100 / `it` 100) — everything Step 7 shipped. Step 9's per-dwelling RNG is
seeded `"s9|<seed>|<hid>"` and appliance ownership is drawn per `hid`. Therefore:

🔴 **TWO FLATS THAT DREW THE SAME HOUSEHOLD HAVE IDENTICAL LOADS. The stock population has thousands
of BUILDINGS and at most ONE HUNDRED DISTINCT OCCUPANCY DIARIES PER FOLD, and on this Step 7
emission it cannot have more.** Seen on the fixture: 170 flats over **6** buildings already bind to
**59** of the 100 households; at full scale it saturates.

⚪ **§1.1's claim is not wrong, it is narrower than it reads.** Step 11 is the first configuration
with that many buildings, that much geometry and one shared weather file. It is **not** the first
with that many distinct occupants. An R² improvement at stock scale would then be evidence about
**spatial and geometric aggregation**, not about occupant diversity — and stating it the other way
would be the cross-population comparison `G11.16` calls a **FAIL**.

### 3.1 🔴 THE DECISION THE RUNNER REFUSES TO MAKE — `--diary-diversity`

| mode | what it does | cost | what a stock number then means |
|---|---|---|---|
| `replicate` | one trigger run per **household** (100/fold), replicated onto every flat that drew it | ~2 min/fold | variance comes only from **which** household a flat drew |
| `reseed` | one run per **flat**, `"s11\|<seed>\|<hid>\|<building>\|<unit>"`, ownership redrawn per flat | ~1.2 s/flat → Bologna Case B alone ≈ **9 h**, `sbatch` work | appliance diversity grows with `N`; **occupant diversity still does not** |

🔴 **The flag has NO DEFAULT and the run refuses without it (`S9`).** A default would have silently
decided what a stock-scale number means. Whichever is chosen is **stamped into every manifest**.
⚪ A third option exists and is **not** this runner's to take: widen the Step 7 diary pool. That is a
new Step 7 emission and a new Step 8 bundle, it would break `build_dwellings`'s reproduction guard
against the shipped bundle, and it re-opens two closed steps. **Named, not done.**

### 3.2 `G11.16` is written, not checked afterwards

Every manifest carries a `declaration` block naming the population, the district, the fold, the
spatial extent, the weather file sha256, the arm, the accounting paths, the `C2` cell-set digest —
and `n_distinct_diaries`, `diary_pool_size`, `diary_diversity_mode` with the note above. **No
aggregate can be produced by this tool without one.**
