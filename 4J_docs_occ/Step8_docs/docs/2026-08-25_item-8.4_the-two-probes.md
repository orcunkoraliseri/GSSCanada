## 1. WHY 8.4 EXISTS AT ALL

8.3 scored fourteen gates over 88 cells and could not touch two of them:

| gate | why the control could not evaluate it |
|---|---|
| `G8.8` scenario differentiation | the control has exactly ONE scenario. One scenario cannot differ from itself, so the gate would have been vacuously clean. |
| `G8.9` stale-output guard | the 8.3 runner has no skip-if-done cache at all. A guard over a cache that does not exist is a guard over nothing. |

Both are 3J's own defects. In 3J two nominally different scenarios wrote byte-identical result
files across all 56 cells while every value check passed — because the values being checked were
the same values twice. That is the class this work item exists to make impossible before 510
archetype-runs are spent on it.

🔴 **The rule this item is built on: a gate never seen failing is a decoration.** Both probes
therefore run twice — once on a correct cell, once on a cell broken on purpose — and the tool exits
non-zero unless the gate falls on the broken one.

## 2. WHAT WAS BUILT, AND WHY IT IS NOT A THROWAWAY

`tools/4thJ_step8_scenario.py` — the scenario path and its cache key. **8.5 imports this module
rather than re-implementing it**, so the thing the probes proved is the thing that will run the
campaign. It is deliberately small.

A scenario is applied exactly as `D-S8-2` item 5 (ruled (c), pre-registered) specifies:

```
phi_int(t) = (1 - f) * 3.0  +  f * 3.0 * g(t) / mean_year(g(t))
```

The IDF carries the watts as `OtherEquipment E_PHI_INT`'s Design Level and the shape as its
Schedule Name, so the injector writes the multiplier

```
m(t) = (1 - f) + f * g(t) / mean_year(g(t))
```

and re-points `E_PHI_INT` at a `Schedule:File` reading it. **The mean of `m` is exactly 1.0 by
construction and is asserted, not trusted**, so the design level never moves and the annual mean of
`phi_int` stays exactly 3.0 W/m² at every `f` — which is what the pre-registration says.

### Three traps met on the way, each already met once in this project

* 🔴 **`ScheduleTypeLimits Frac` is 0.0–1.0 and EnergyPlus clips to it.** `m(t)` exceeds 1.0
  wherever a household is more present than its own annual mean — for the probe's household, up to
  1.182. Re-using `Frac` would have silently flattened every peak this paper is about. A separate
  `PhiMult` limit (0–100) is written and `inject()` **refuses** `Frac` by name.
* **`Interpolate to Timestep` must be `No`** (`G8.13`) and the model runs at `Timestep 6`. It is
  written `No` and read back out of the *saved* IDF. See `FINDING 126` — this is where it bit.
* **The cache key must contain every input that can change the result.** The broken key lives in the
  same module, named `naive_cache_key`, so the probe can be seen firing on it. Nothing in a runner
  may call it.

`tools/4thJ_step8_probes.py` — work item 8.4 itself. It imports the bands (`V8.c`: one source of
thresholds), the 8.3 runner (one runner, one reader) and **the scorer's own `G8.13` function rather
than a second copy of it**.

## 4. 🔴 THE THREE DEFECTS THE PROBING FOUND

### `FINDING 126` — `G8.13` could not see the violation it exists to catch, on the only shape that matters

`G8.13`'s parser read **only the last comma-field** of a schedule object. That is where
`Interpolate to Timestep` sits on a `Schedule:File` written *without* the optional
`Minutes per Item` — which is exactly the shape 8.3's injection `I9` used, so the gate was recorded
as **seen firing**. A real `Schedule:File` carries `Minutes per Item` after it, and on that shape
the `Yes` was invisible: the gate returned no violations and the row read PASS.

Measured, on four shapes:

| IDF shape | before | after |
|---|---|---|
| the control (`Schedule:Constant` only) | `([], 0)` → `NOT_EVALUABLE` | unchanged |
| 8.4's injected 9-field object, `No` | `([], 1)` → PASS | unchanged |
| 🔴 **8.4's injected 9-field object, `Yes`** | 🔴 **`([], 1)` → PASS** | 🟢 **`(['schedule:file'], 1)` → FAIL** |
| 8.3's `I9` 8-field object, `Yes` | `(['schedule:file'], 1)` → FAIL | unchanged |

**The first real `Schedule:File` in this project is 8.4's own injected IDF, which is why it
surfaced here and not in 8.3.** Two causes, both fixed **additively**: the field is now read *by
position* for `Schedule:File`, and comments are stripped **per line** first — IDF writes
`value,  !- Field Name`, so a trailing comment belongs to the field *before* the comma and splitting
on `!` after splitting on `,` mis-aligns every field in the object.

🟢 **Nothing that used to fire stopped firing.** A new injection `I13` was added to the 8.3 battery
using the shape the real injector writes, so the fix is tested on the case it was made for and not
on its own convenience case. The battery is now **13 of 13 HIT**, and `I9` and `I13` both fell
`G8.13`.

### `FINDING 127` — `G8.10`'s note read "worst fuel: all zero" on all 88 control cells, and the gate was live

`worst_fuel` was only assigned when a deviation *exceeded* the running worst, so a deviation of
exactly 0.0 left it empty and the note fell back to the literal `all zero`. Read plainly, that says
*nothing was compared*. What was actually compared, on every cell: **District Heating Water,
97.99 GJ of end uses against a 97.99 GJ total, closing at exactly 0.0000 %.**

The gate was never broken; its note was. But "all zero" and "nothing to compare" are the two
readings a vacuity guard exists to keep apart — `FINDING 95`'s lesson — so the note now counts the
fuels **actually** compared and says `VACUOUS` only when there are none. ⚪ 8.3's record said "the
ELECTRICITY arm is vacuous here", which was and remains true: `Electricity [GJ]` is 0.0 in both the
end uses and the total.

### `FINDING 128` — the pre-registered sweep is a PEAK channel, not an annual-energy channel

On this one archetype, going from `f = 0.00` to `f = 1.00` — the full width of the pre-registered
sweep — moves:

| quantity | change |
|---|---|
| annual heating | **+1.60 %** (97.99 → 99.56 GJ) |
| peak heating | **+10.84 %** |
| peak hour | 8672 → **8671**, one hour earlier |

🔴 This sharpens `FINDING 125` from a ceiling into a measurement. `FINDING 125` established that
switching `phi_int` off *entirely* is worth only +40.5 / +19.7 / +20.1 % on annual heating and that
the sweep merely **redistributes** it; 8.4 measures what that redistribution is actually worth, and
on annual energy it is **+1.6 %, not 15–50 %**. The annual mean is held at exactly 3.0 W/m² by
construction, so this is arithmetic, not a surprise — but it is the first time the number exists.

⚪ **One archetype, one household, one fold. This is NOT a campaign result** and it is not quoted as
one; 8.5 is what measures it over 88 archetypes × 5 levels. What it does establish is *where to
look*: the occupancy channel this paper opens lives in peak magnitude and peak timing.

### `FINDING 129` — the injected path at `f = 0` reproduces the 8.3 control byte-for-byte

`series_hourly.csv` from the `f = 0.00` injected run is **byte-identical** to
`control/es_AB_ES01/series_hourly.csv` (`22677b61…`). A flat multiplier delivered through
`Schedule:File` gives exactly what `Schedule:Constant` gave.

🟢 That is `D-S8-2` item 5 (c)'s entire point, measured rather than argued: **`f = 0` is an endpoint
of the sweep and not a separately constructed control**, so "the control was built differently" is
not available as an objection to anything 8.5 reports.

## 7. WHAT 8.5 INHERITS

1. **Import `tools/4thJ_step8_scenario.py`.** Do not re-implement the injector; the probes proved
   *that* module.
2. 🔴 **Name the multiplier file deterministically per (cell, schedule, `f`).** The cache key

3. **`G8.12` and `G8.16` are still not evaluable** and become so in 8.5, where a Step 7 schedule
   enters a campaign cell for the first time. `V8.g`'s arm is already armed.

## ADDENDUM, 2026-08-25 (night) — 🔴 `FINDING 128`'s MAGNITUDES ARE SUPERSEDED. ITS DIRECTION IS NOT.

Work item 8.5 found that the artefacts these probes ran on were wrong in two ways that leave no trace
in the energy, and both have since been fixed and guarded:

* **`FINDING 130`** — the diaries were the **Leg-4 pilot**, whose own records stamp themselves
  `LEG-4 PILOT -- NOT REPORTABLE`. The schedule emitter had the leg hard-coded, so the Leg-5 pools
  (`Olmo-3-1025-7B`, 5,200 diaries per fold, the reported leg) had been on disk since 2026-08-24 and
  no code path could reach them.
* **`FINDING 131`** — the bundle was emitted on calendar **2010**, whose 1 January is a **Friday**,
  and wired into the 8.1 IDFs' **Sunday**-start `RunPeriod`. Every synthetic Saturday landed on a
  Thursday for fifty-two weeks. `FINDING 99` predicted exactly this.
* **`FINDING 132`** — the multiplier was written at `%.6f`, so the artefact's annual mean sat
  4.01e-07 away from the pre-registered exactly-1.0.

**The probes were re-run on the corrected artefacts and still read `PASS --- 10 of 10 checks ok`,
6 runs, 0 severe.** `G8.8` and `G8.9` are gates about wiring, and the wiring conclusion is unchanged.

🔴 **What does change is `FINDING 128`'s numbers.** On the same archetype and the same `f = 0 → 1`
comparison, the corrected artefacts read **+0.18 % annual heating and +7.70 % peak**, against the
+1.60 % / +10.84 % recorded above. And at campaign scale (88 cells × 10 diaries, work item 8.5) the
**annual** median is within ±0.06 % in two folds of three, while the **peak** median is
+6.38 / +4.54 / +3.96 %.

So `FINDING 128`'s reading — *the occupancy channel is a PEAK channel* — **stands and is
strengthened**; its magnitudes are superseded by **`FINDING 133`**, and the annual figure quoted
above should never be cited. This section is an addendum rather than an edit: a record that is
rewritten to agree with a later run is not a record.
